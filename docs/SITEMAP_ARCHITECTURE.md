# Sitemap & Content-Sync Architecture

Last updated: 2026-05-20

This document is the source of truth for how `/blog/*` URLs end up in
`https://lsdiet.com/blog-sitemap.xml`, and how Contentful publishes flow
through to a deployed sitemap without manual intervention.

---

## 1. Where sitemap truth originates

The **Supabase Edge Function `blog-sitemap`** is the live source of truth.
On every request it merges three sources:

| Layer       | Lives in                                 | "Published" means                                  |
| ----------- | ---------------------------------------- | -------------------------------------------------- |
| Foundations | `src/content/foundations/index.ts` (TSX) | Slug appears in the registry → ships on next deploy |
| Articles    | `src/content/articles/index.ts` (TSX)    | Slug appears in the registry → ships on next deploy |
| Contentful  | Contentful space `master` env, `blogPost` | Editor clicks **Publish** → webhook below          |

Precedence on slug collision is locked: **Foundations > Contentful > Articles**.
Same precedence used by `src/lib/blogIndex.ts` so the on-page index and the
sitemap can never disagree.

The branded URL `https://lsdiet.com/blog-sitemap.xml` is served as a static
file from `public/blog-sitemap.xml`. That file is a **cache** of the edge
function's output, regenerated by `scripts/generate-blog-sitemap.ts` during
`predev` and `prebuild` (wired in `package.json`).

```
GET https://lsdiet.com/blog-sitemap.xml
        │
        ▼  (static file, served by Lovable hosting)
public/blog-sitemap.xml
        ▲
        │  written by `bunx tsx scripts/generate-blog-sitemap.ts`
        │  on every `vite dev` and `vite build`
        │
        ├── Foundations  (src/content/foundations)
        ├── Articles     (src/content/articles)
        └── Contentful   (fetched live by the edge function)
```

### Why a static cache instead of pointing the sitemap index at the edge function

Keeps the canonical URL on `lsdiet.com` (no Supabase function domain
leaks into anything Google or users see). The cost is that Contentful
publishes must trigger a rebuild — handled by the webhook below.

## 2. Foundations & Articles (code-managed)

These are the authority layer and the high-volume search layer. They are
**not** in Contentful by design — full control over interlinking, schema,
URL permanence, and TSX rendering.

Workflow for the developer / agent:

1. Add a new TSX file in `src/content/foundations/` or `src/content/articles/`.
2. Append it to the corresponding `index.ts` registry.
3. Mirror the new slug into the matching list in
   `supabase/functions/blog-sitemap/index.ts`
   (`FOUNDATION_SLUGS` or `ARTICLE_SLUGS`). The edge function is a Deno
   sandbox and cannot import from `src/`, so this mirror is required.
4. Commit. Deploy regenerates the static sitemap automatically.

> **Governance**: `supabase/functions/blog-index/GOVERNANCE.md` covers slug
> immutability, canonical-topic enums, and the precedence rule.

## 3. Contentful sync (webhook → rebuild)

```
Editor clicks "Publish" in Contentful
        │
        ▼
Contentful webhook POSTs to:
  https://joohccchfpcshlihctsm.supabase.co/functions/v1/contentful-rebuild-hook
  Headers: X-Webhook-Secret, X-Contentful-Topic, X-Contentful-Webhook-Name
        │
        ▼  filters (drops drafts, non-master, non-blogPost)
        ▼  debounce (collapses bursts within 120s)
        ▼  event idempotency (X-Webhook-Name + sys.id + sys.updatedAt)
        │
        ▼
POST https://api.github.com/repos/<owner>/<repo>/dispatches
  event_type = "contentful-publish"
  client_payload = { dispatchId, eventId, topic, entryId, updatedAt }
        │
        ▼
.github/workflows/contentful-rebuild.yml
  → writes .lovable/last-content-sync.json
  → git commit + push
        │
        ▼
Lovable GitHub sync detects the push → auto-deploy
        │
        ▼
`prebuild` runs scripts/generate-blog-sitemap.ts
  → fetches blog-sitemap edge function (which now sees the new Contentful entry)
  → overwrites public/blog-sitemap.xml
        │
        ▼
Fresh https://lsdiet.com/blog-sitemap.xml live (typical lag: 60–120s)
```

### 3a. Webhook filters (resilience & idempotency)

The edge function `contentful-rebuild-hook` enforces:

| Rule                  | Behavior                                                                       |
| --------------------- | ------------------------------------------------------------------------------ |
| Shared-secret auth    | Requires `X-Webhook-Secret` header to equal `CONTENTFUL_WEBHOOK_SECRET`; else 401. |
| Topic filter          | Only `ContentManagement.Entry.publish` / `.unpublish` dispatch. Drafts return 200 no-op. |
| Environment filter    | Only `sys.environment.sys.id == master` dispatches. Others 200 no-op.          |
| Content-type filter   | Only `sys.contentType.sys.id == blogPost` dispatches. Others 200 no-op.        |
| Debounce (120s)       | If any successful dispatch happened in the last 120s, return 200 `debounced`. Bulk publishes collapse into one rebuild. |
| Event idempotency     | Same `eventId` repeated → 200 `idempotent`, no second dispatch.                |
| GitHub failure        | Returns 5xx so Contentful retries with backoff.                                |
| Loop safety           | The rebuild never writes back to Contentful, so it cannot cause a loop.        |

Debounce + idempotency rows live in the `public.rebuild_dispatches` table.
RLS blocks anon and authenticated reads/writes — only the service role
(used by the edge function) can touch it.

### 3b. Contentful webhook configuration (one-time setup)

In Contentful → **Settings → Webhooks → Add Webhook**:

- **URL** — `POST https://joohccchfpcshlihctsm.supabase.co/functions/v1/contentful-rebuild-hook`
- **Triggers** — choose **Select specific triggering events**, enable
  `Entry → Publish` and `Entry → Unpublish` only. Leave save/auto-save off.
- **Filters** —
  - `sys.environment.sys.id` equals `master`
  - `sys.contentType.sys.id` equals `blogPost`
- **Headers** —
  - `X-Webhook-Secret: <CONTENTFUL_WEBHOOK_SECRET>` (mark as secret)
  - `Content-Type: application/json`
- **Payload** — default (Contentful sends the entry payload).

### 3c. Required secrets

Set via Lovable Cloud → Secrets:

| Secret                       | Purpose                                                              |
| ---------------------------- | -------------------------------------------------------------------- |
| `CONTENTFUL_WEBHOOK_SECRET`  | Shared secret matched against the webhook header.                    |
| `GITHUB_DISPATCH_TOKEN`      | Fine-grained PAT, scope `Actions: read/write` on this repo only.     |
| `GITHUB_REPO`                | `owner/repo` string for the dispatch API URL.                        |

## 4. Failure modes & recovery

| Symptom                                          | Likely cause                                                | Recovery                                                                                  |
| ------------------------------------------------ | ----------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| New Contentful post missing from sitemap         | Webhook didn't fire or was filtered out                     | Check Contentful → Webhooks → activity log. Confirm topic, env, content type match filters. |
| Webhook fires but sitemap unchanged              | GitHub dispatch failed                                      | Check Supabase function logs for `contentful-rebuild-hook`. Verify `GITHUB_DISPATCH_TOKEN` not expired. |
| GitHub Action runs but no commit                 | Marker unchanged (rare; only if duplicate dispatch)         | Trigger another publish or manually push any commit.                                       |
| Sitemap stale across the board                   | Static file wasn't regenerated                              | Force a redeploy. Or run `bunx tsx scripts/generate-blog-sitemap.ts` locally and commit. |
| Need to force-refresh without a Contentful event | Manual rebuild                                              | Push any commit (e.g. bump `.lovable/last-content-sync.json` manually) or click Publish in Lovable. |

To verify the sitemap is fresh:

```bash
curl -sI https://lsdiet.com/blog-sitemap.xml | grep -i last-modified
curl -s https://joohccchfpcshlihctsm.supabase.co/functions/v1/blog-sitemap \
  | grep -c "<url>"
```

The second number should match foundations + articles + Contentful count.
The edge function also returns `X-Sitemap-Count`, `X-Sitemap-Foundations`,
`X-Sitemap-Articles`, and `X-Sitemap-Contentful` headers for quick checks.

## 5. Adding new content types

If we add another code-managed content layer (e.g. case studies):

1. Create `src/content/<layer>/index.ts` and the rendering hook in
   `BlogPostPage.tsx` if URLs live under `/blog/*`.
2. Add the layer to `src/lib/blogIndex.ts` with explicit precedence.
3. Mirror the slug list into `supabase/functions/blog-sitemap/index.ts`.
4. Update this document.

If we add another Contentful content type that should appear on `/blog/*`:

1. Extend the Contentful query in `blog-sitemap/index.ts`.
2. Extend the topic/content-type filter in `contentful-rebuild-hook/index.ts`.
3. Update the webhook filter in Contentful (Section 3b).
4. Update this document.
